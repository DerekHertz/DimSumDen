# 08: Size the review relay to the risk of the diff

**Type:** task (it changes genomes, so every change is a brain gate)

**What to build:** Run the full `security` cell only when a diff touches something risky:
- dependencies or the lockfile
- CI workflows or branch protection
- network or IPC code
- shelling out to other programs
- board, lock or daemon code
- secrets handling

Every other diff gets a scripted check instead: a secret scan plus "no dependency or lockfile change", run by `scout` or CI, and it escalates to the full cell on any hit. In the same spirit, `qa verify` can be light when qa wrote the tests in `specify` mode: rerun them, confirm no test was weakened, and spot-check the criteria.

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] A written rule, for the orchestrator genome and the code relay, for when to run full security and when to run the scripted check; the scripted check itself is a committed script
- [x] A light and a full qa verify, told apart by whether qa specify ran
- [x] The genome changes are proposed to the user before editing (brain gate)

Confirmed by direct test: `node scripts/risk-check.mjs "--output=pwned.txt"` writes an (empty) `pwned.txt` via git's own `--output=` option, and because stdout is now empty, risk-check itself prints `risk-check: clean` and exits 0. A crafted range therefore both writes to an arbitrary path and forces a false "clean" verdict — defeating the exact gate this script exists to provide. Not reachable today (the orchestrator invokes it with no argument), but the script's documented contract takes an arbitrary caller-supplied range, and the ticket's own framing anticipated this as the surface to check. Fix: reject a range starting with `-`, or insert `--end-of-options` before it in the argv array.
  - **MEDIUM — `scripts/risk-check.mjs:33`:** the "shelling out" pattern `\b(spawn|execFile|execSync)\s*\(` does not match `execFileSync(` — "execFile" is followed by "Sync(" not "(", so neither alternative fires. Since only added (`+`) lines are scanned, a diff that adds an `execFileSync(...)` call without touching an already-present `child_process` import line evades detection entirely — a false negative inside the "shelling out" category the ticket asked me to check. Non-blocking alone, but compounds with the finding above.

The other fixtures are confirmed safely below real thresholds: no `AKIA` string used anywhere, and the Stripe-shaped `sk_live_1234567890abcdef` is 16 chars after the prefix, under GitHub's 24-char minimum for that pattern. Worth a real scan or a non-PEM-shaped placeholder if push protection is ever enabled.
